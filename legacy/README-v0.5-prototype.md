# Lode Runner 3D — 原型设计与开发文档

> 版本：v0.5 原型 ｜ 日期：2026-09-10 ｜ 状态：核心机制全部验证通过，可玩（5 关）
> 文件：`proto.html`（单文件游戏，双击即玩）+ `test.js`（无头回归测试）

---

## 1. 项目定位

经典《淘金者》(Lode Runner, 1983) 的**真 3D 化重构**。不是把 2D 关卡贴到平面上，
而是回答一个问题：**哪些谜题只有在 3D 里才存在？**

### 前人尝试与本作的差异
| 作品 | 做法 | 遗留问题 |
|---|---|---|
| Lode Runner 3-D (N64, 1999) | 关卡 3D 化，角色沿轨道走 | 镜头遮挡被广泛批评 |
| Cubic Lode Runner (PS2, 2003) | 立方体关卡 + 整关旋转 | 4 向逃跑稀释了追逃张力 |
| **本作** | 砖体贯穿 Z 轴的双层迷宫 | 把 3D 从"视角噱头"变成**信息不对称机制** |

### 设计支柱（全部已在原型中验证成立）
1. **镜头不挡路** — 近正前视角 + Q/E 小角度摆动（±1.25rad），关卡全景始终可读
2. **挖坑链条完整** — 挖→坠落→回填被埋→敌人以身填坑
3. **Z 轴 = 信息维度** — 砖墙贯穿前后两层：金子/守卫可藏在背面，
   **旋转镜头从"看风景"变成"获取信息"**，这是 2D 版物理上做不到的设计素材
4. **规则忠实原版** — 横杆可吊挂穿行、守卫同样会用杆（1983 行为）、
   杆下/梯井不可挖（护绳规则）、无跳跃

## 2. 玩法与键位

| 键 | 动作 | 键 | 动作 |
|---|---|---|---|
| A / D | 左右走 | J / K | 挖左下 / 右下砖 |
| W / S | 爬梯 / 下梯 / 杆上攀 | L | 站梯上垂直连挖 |
| 空格 | 跳下沿口 / 杆上松手 | Q / E | 旋转镜头 |
| Z / X | 隧道口换前/后层 | R | 重开本关 |

**目标**：收集全部金子 → 出口 E 生成通天梯 → 爬顶过关。3 条命。

### 五关节奏
1. **L1** 教学：纯挖坑埋守
2. **L2** 双层入门：背面藏 3 金 + 隧道口（提示转镜头）
3. **L3** 横杆关：悬空走廊 + 梯井 + 桩墙
4. **L4** 组合考试：杆 + 背面层
5. **L5** 终关：信息不对称完全体

## 3. 规则规格（实现口径，与 test.js 一一对应）

### 网格模型
- 字符砖：`#`可挖砖 `=`硬砖 `.`通道/平台 `'~'`空气 `'o'`坑（4s 回填）
- 叠加特征：`l`梯（砖墙梯井不可挖）`b`横杆 `'t'`隧道 `G`金 `p`/`e`/`E`
- **平台即砖块**：通道行的支撑物就是下一行的砖；挖掉支撑 = 地面塌落
- 砖体（# / = / o）在 Z 轴贯穿前后两层（厚 2L）；梯/杆/金/隧道逐层独立

### 坠落与坑
- `fallTarget()`：竖直下落 → 坑=被埋(死/守卫阵亡)，杆=自动抓住(catchBar)，
  梯井=安全停靠，硬砖上表面=落地
- 掉进坑：玩家扣命；守卫被埋 2.4s 后于出生点复活，掉落所携金子
- 玩家从高处砸落到守卫头顶不杀守卫（原版），触碰即死

### 回填加速三档（"聪明的老守卫"）
| 条件 | 倍率 |
|---|---|
| 基础回填 | 4.0s |
| 任何角色走过坑正上/隔上一格 | ×5 |
| **守卫被埋在坑内（以身填坑）** | ×10，封顶后复活 |
| 新鲜坑（<2.2s）坑口守卫停顿 0.25s 再踩（试探行为） | — |

### 横杆
- 杆在空气行 `~`，下方必须悬空（构建期校验：bar-over-solid 报错）
- 玩家与守卫都可：从通道行 W 上攀抓杆 / 沿杆横移 / 杆尽头 hop 上平台 / 空格松手坠落到下层杆（可连锁）
- **杆正下方的砖不可挖**（原版护绳规则）
- 头顶"通道"实为假砖：走过去失去支撑即坠落，可精准落到杆上或穿透多行杆列

### Z 轴双层
- 隧道口必须前后同坐标成对（loadLevel 自动配对校验，不成对则忽略）
- 站在隧道口按 Z/X 换层，0.3s 硬直（防连点）
- 金子/守卫/梯子逐层独立；异层接触**不**死亡；守卫发现目标异层 → 奔向最近成对隧道换层追击（0.4s 换层动画停顿）
- 出口仅在前层（通关动线闭环）

### 守卫 AI（经典两段式 + 3D 扩展）
1. 同层：先对高度（梯上/缺口掉），再水平逼近
2. 会拾取路径上的金子（限 1 块），被埋时掉落可捡回
3. 会用杆追击（忠实 1983）
4. 异层：tunnelTarget() 寻最近隧道，跨层追击

### 胜负
- 集齐金子 → `openExit()`：出口列打通（跳过杆行，逐格铺梯）→ 绿色门
- 碰到同层守卫 / 被埋 → 死一条命；3 命耗尽 Game Over → R 重开

## 4. 技术说明

- **单文件零构建**：HTML + 原生 JS + Three.js r160（CDN）。~500 行
- 渲染：InstancedMesh 批量砖块/坑/硬砖；梯子杆件为普通 Mesh（数量小）
- 逻辑 100% 与渲染解耦：状态是纯 tile 数据（`sol/ff/bf/golds/enemies`），
  函数签名 `walk/climb/dig/...` 不碰 Three.js → **可无头测试**
- `preserveDrawingBuffer` 已开启（截图/像素探针需要）
- 关卡即字符串数组：`LEVELS=[{f:[行...], b:[行...]}]`，b 缺省=单层关
- 镜头跟随：玩家位置 30% 权重缓动跟随时保持全局可读

## 6. 已知问题与坑（踩过的，勿重蹈）

1. **DH 必须在角色生成前赋值**——否则 tileW 用旧 DH 算出偏移坐标（v0.3 曾全员错位）
2. **front 层 `t` 字符要落成 `.` 通道**，不能原样进 sol（v0.4 隧道"不可进入"根因）
3. **readPixels 必须在渲染帧后取样**（先 requestAnimationFrame 再读），preserveDrawingBuffer 关不掉
4. **细杆在 37 单位外不可见**——小截面物件要么加粗要么自发光（0.045→0.16 + emissive 才通过视觉复核）
5. **vision 审查不可省**：代码正确 ≠ 渲染可见，L3 杆"逻辑存在但像素为 0"骗过了两轮 DOM 检查
6. `new Function` 沙箱里 getter 与 setter 名不能相同（`set key(k,v)` 与 `get keys` 冲突过一次）
7. 守卫 AI 与玩家共用 moveTo/beginFall，改移动函数必须同时跑 AI 回归
