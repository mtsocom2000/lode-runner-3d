# 立方角隙（Cube-Corner Lode Runner 3D）

一个把 Lode Runner 折进**墙角**里的 3D 版本：两片墙沿中线折成 90°，于是"左右"在折痕处
会**原地转 90°**，而一整张关卡仍然是你熟悉的**一维字符串数组**。v1 目标：**双击一个 HTML
就能玩、能自己画关卡**。

- **玩**：双击 `dist-single/index.html`（单文件、无依赖、不用起服务器）。
- **画**：在页面里按 `Tab` 打开编辑器 —— 见下面[画关卡](#画关卡)。
- **约定与门禁**（给改代码的人 / AI 助手）：见 [`AGENTS.md`](AGENTS.md)。
- **设计文档**：[可行性评估与架构设计](doc/立方角隙-可行性评估与架构设计.md)、
  [任务分解与开工计划](doc/立方角隙-任务分解与开工计划.md)。

## 怎么玩

**目标**：取走关卡里**所有**宝物 → 出口两侧的**闸门（假砖）消失** → 走进出口过关。

| 键 | 作用 |
|---|---|
| `W` `A` `S` `D` / 方向键 | 移动（墙上：`W`/`S` 上下爬、`A`/`D` 沿墙；甲板上四个键对应四个斜向） |
| `Q` / `E` | 朝**后下方** / **前下方**挖一格（只能挖可挖砖 `X`；挖出来是个**坑**，掉进去或被埋都会少一条命） |
| `Z` / `X` | **只在甲板上**换层（爬塔）；墙上不做事 |
| `S` | 站在"丁字路口"那一格时按 `S` 拐上小道 |
| `R` | 重开本关 |
| `N` | 过关后进下一关（该关配了"下一关"时，HUD 会提示） |
| `Tab` / `Esc` | 开关关卡编辑器 |

**命**：3 条。落水、被埋、被看守抓到都会少一条。

**看守**两种：**无人机**只在墙面内巡逻（不会上小道），**攀爬者**更慢，但会上小道、也会吊杆。

## 折痕：本作唯一需要先讲清的一件事

两片墙是**同一张平面折了 90°**：摊平时 `cols` 列被折痕分成左（A 面）与右（B 面），
折痕两侧**最内列**（`col = fold-1` 与 `col = fold`）在世界里**落在同一个点**。

由此有三条后果，编辑部已经为它们栽过几次跟头，所以宁可写在这里：

1. **过折痕 = 原地转 90°**，不是走一格；
2. 因此**两格各自都要"站得住"**才过得去 —— 你看着是同一格，脚下踩的却是**两条列各自的下一行**。
   有一侧是空的，走过去就是落水。编辑器把这种"看着能过、实际会掉"的情形报成
   **折痕两侧对不上**（红框）；
3. 落笔时**两格成对**写（砖 / 硬砖 / 空 / 梯 / 杆都成对；宝物与出口这类"物件"不成对）——
   所以你在折痕那一列点一下，两面会一起画。

## 画关卡

按 `Tab` 打开编辑器。面板从上到下：**关卡库 → 工具栏 → 校验清单 → JSON 文本框 → 一排按钮**。

**工具栏（16 支笔）**：砖 `X`、硬砖 `=`、空 `.`、梯 `H`、杆 `-`、宝物 `G`、出口 `E`、
甲板「板 / 板·杆 / 板·梯」、**接头**（甲板 ↔ 墙面那道口子：先点甲板格、再点墙面格）、出生点、
看守「无人机 / 攀爬者」、宝物（甲板）、橡皮。每支笔名旁边直接印着它的说明。

**手势**（这三条是让画关卡**真的能用**的关键）：

- **点一下**落一格；**按住拖**连续落笔，中间跳过的格子会自动补齐（快拖不会画成虚线）；
- 按住 **`Shift` 拖 = 矩形整片铺**（铺墙、铺地板最快的方式；松手才落笔，撤销是一步）；
- **撤销 / 重做**：`Ctrl+Z` / `Ctrl+Y`，或面板上的两个按钮。**一步 = 一笔**（含一次矩形）。

**关卡库**：一张图一个**槽**（不再"新建一关 = 扔掉上一关"）。下拉选关，`新建` / `删除` 在旁边；
每个槽还能指定**下一关**，于是可以把你自己那几关串成一条链。首次打开时，老版本存的那一张会自动迁进来。

**校验**：面板里的清单逐条用中文说明（`✗` 错误 = 玩不了、`⚠` 提醒 = 能玩但大概没画完），
场景里对应**红框 / 灰框**。悬停任意一格会告诉你**这一格是什么**（含"这块硬砖是闸门"这种
**在画面上看不出来**的情形）以及**站不站得住、为什么**。

**试玩**：按钮「试玩」会应用当前 JSON 并关掉编辑器；回来按 `Tab`。

**导出 / 导入 JSON**：`导出 JSON` 落一个文件，`导入 JSON…` 读回来；也可以直接在文本框里改
—— 关卡就是一串等长字符串，`r0` 是**最下面那一行**（面板里写了这一句，因为第一次自己猜出来
是要绕的）。

## 想改代码

```bash
npm install
npm run dev        # 开发服务器（改源码即时生效）
npm run pack       # 产出 dist-single/index.html —— **交付的就是它**
npm run probe      # 先 pack，再用无头 Chrome 对**真实产物**做像素断言
npm run shot       # 出一张截图（tools/out/page.png）
```

**五个门禁都要绿**：`typecheck` / `lint` / `test` / `probe` / `pack`（见 [`AGENTS.md`](AGENTS.md)）。

三条架构红线（改之前请先读它们）：

- `src/core/` **零 three、零 DOM** —— 规则层不许知道渲染；
- sim 是**确定性**的：同一个 `(state, intents)` 永远给同一帧，可以 replay 逐字节比对；
- **判据只能有一个出处** —— 别在第二处重新推导同一件事（几何在 `render/metrics.ts`，
  关卡合法性在 `core/level/validate.ts`，键位解释在 `rules/movement.ts`）。

```
src/core/      规则与数据（无渲染）：sim / world / rules / level
src/render/    渲染层（只读 state 与 events）：scene / meshSync / fx / metrics / palette
src/app/       胶水：main / editor / levelstore / hud / input / sfx
tools/         probe / shot（无头 Chrome）
test/          vitest（规则层为主；渲染层另有 probe 在真实产物上守）
```
