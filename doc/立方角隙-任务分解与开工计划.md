# 《立方角隙》任务分解与开工计划

> 版本 **v2.0** ｜ 2026-09-13 ｜ 前置文档：`doc/立方角隙-可行性评估与架构设计.md`（**v2.0 折面原版关卡**）
> 变更：v1.2 → v2.0 —— **概念整体替换**。删除原 v1.2 的全部任务（高度场/墙深度网格/台地/峰群/横杆等高锚点/魔梯/X-ray）。
> 状态：**等待用户确认折面方向（v10 方向稿已开实时预览窗口）+ 裁定架构文档 §八 的 5 个开放问题 → 启动 T0**

## 技术决策（已定，T0 直接落地）

- **UI 用原生 DOM，不引入 React**（理由见架构文档 §5.1）。`app/` 层保持无框架依赖，为将来的关卡编辑器/设置页留迁移位。
- **打包产物不要求"部署"**：`npm run build` 出纯静态 `dist/`；另用 `vite-plugin-singlefile` 出 `npm run pack` → 单个 HTML，**双击即玩、可直接发给他人**（与当前 mock 的使用方式一致）。
- 旧文件（原型、旧 README、旧企划案）**已归档至 `legacy/`**，见架构文档附录 A。

## 里程碑

- **M0 决策门（当前）**：确认 `mocks/cube-fold-mock-v10.html` 方向；并裁定 5 个开放问题（岛台数量 / 敌人落水行为 / 关卡规模 / 折痕朝向 / 出口规则）
- **M1 可走通的折面**：折面关卡渲染（统一立方体砖）、**折痕通行**、原版走/梯/杆/跳下、输入映射（含折痕朝向）+ 手感 Spike gate
- **M2 水面与博弈循环**：水面渲染 + **两条落水途径**、岛台/小道数据与渲染、原版挖/回填/活埋、无人机、宝物 → 出口通天梯、3 命、L1 可通
- **M3 收尾与扩展**：攀爬者、L2/L3、规模放大、全量回归、视觉打磨 → v1 发布候选

## 纪律（继承原型教训 + 本轮新增）

1. core 零 three/DOM（lint 强制）。
2. 机制先无头用例、后渲染接入；**改移动 / 坠落 / 横杆函数必跑 AI 回归**。
3. 每里程碑出口做截图 / 像素探针复核（"代码对 ≠ 像素对"）。
4. 物件要么够粗要么自发光；角色由渲染层级保证始终可见。
5. **新增：提交前必须过 `validate`（可达性）**——本轮教训：v6/v7/v8 反复出现"看着有台子却上不去"。任何 mock 或关卡在交付前先跑校验，可达不合格不交付。

## 预估

规则集＝**原版规则的直接移植**（原型已实现并跑过 25 项无头回归）＋ 3 条新规则（折痕边 / 水面不可走入 / 两条落水途径）。
单人 + agent：M1 约 2.5 日、M2 约 2.5 日、M3 约 3 日，**合计约 8 个实现日**（不含试玩反馈轮与规模放大）。
相比 v1.2 计划减少：无高度场/深度网格建模、无横杆等高校验、无 X-ray、无旋转 → 至少省掉 2~3 日。
